# AadiVed Yoga and Wellness: website

Marketing site for AadiVed Yoga and Wellness, a women-owned yoga and sound healing studio in Hinjawadi Phase 3, Pune. Built with Astro 5 (static output), plain CSS and a small vanilla script for the menus.

## Commands

| Command | What it does |
| --- | --- |
| `npm install` | Install dependencies |
| `npm run dev` | Dev server at http://localhost:4321 |
| `npm run build` | Build to `dist/` |
| `npm run preview` | Serve the built site |
| `npm run check:dist` | Fail if `dist/` has any `.jpg/.jpeg/.png/.avif` other than the allowed exceptions |
| `npm run assets:generate` | Regenerate the favicon, touch icon, manifest icons and OG image in `public/` |

Run `npm run build && npm run check:dist` before every release.

## Where things live

- `src/data/site.ts`: phone, address, socials, Google links, navigation, mega menu, footer links and the registry of stub pages. Components never hard-code these.
- `src/data/services.ts`, `src/data/reviews.ts`: homepage service cards and Google reviews.
- `src/pages/index.astro`: homepage. `src/pages/[...slug].astro` generates every other route from `stubPages` in `site.ts`.
- `src/scripts/menu.ts`: mega menu, About dropdown and mobile nav behaviour.
- `design-source/`: the original PNG/JPG files. Not built, not deployed.
- `reference/homepage-mockup.dc.html`: the approved homepage design.

## Image format rules

Every image on the site is WebP, rendered through `astro:assets` with `format="webp"` and explicit dimensions.

**Exceptions (the only non-WebP files in `dist/`)**, all generated by `scripts/generate-icons.mjs` from the vector logo masters in `design-source/` (`aadived-favicon-source-512.webp` for the icons, `aadived-logo-square-olive-2048.webp` for the OG image):

- `og-image.jpg` (1200x630): WhatsApp, Facebook and LinkedIn previews often ignore WebP
- `favicon.ico`
- `apple-touch-icon.png` (180x180)
- `icon-192.png` and `icon-512.png` (web manifest)

`npm run check:dist` fails on any other `.jpg/.jpeg/.png/.avif`. Any new image must be converted to WebP first.

## SEO

- **Titles, descriptions and H1s** for every page live in `src/data/seo.ts`. Titles are 50 to 60 characters with the brand last, descriptions 140 to 160 characters. Pages read their SEO from there, so edit that one file.
- **Structured data** is built from `src/data/site.ts` in `src/data/schema.ts`: `HealthClub` on the homepage (defined once, referenced by `@id` elsewhere), `Service` and `FAQPage` on service pages, `Person` on `/about/anupriya/`, and `BreadcrumbList` on inner pages. FAQ answers that still contain a `[placeholder]` are left out of the schema. Not included because the data is not held: geo coordinates and price range.
- **Open Graph images:** per-page 1200x630 JPGs in `public/og/`, generated by `npm run assets:og` from each hero image. Re-run it and commit when a hero image changes. `check:dist` allows JPGs under `og/` only.
- **`noindex`** on `/privacy/`, `/terms/` and the 404 page. They are excluded from the sitemap (`astro.config.mjs`).
- **`npm run seo:audit`** reads the built `dist/` and fails on missing or duplicate titles and descriptions, titles over 60 characters, descriptions outside 120 to 160, pages without exactly one H1, skipped heading levels, wrong canonicals, missing alt, missing Open Graph tags, invalid or duplicate JSON-LD, orphan pages, and a wrong sitemap or `robots.txt`. Run `npm run build && npm run seo:audit` before each release.

## Journal

Posts are MDX files in `src/content/journal/`. Frontmatter is validated by `src/content.config.ts` (title, description of 140 to 160 characters, pubDate, category, tags, heroImage, heroAlt, relatedService).

- Put the featured image in `src/assets/images/journal/[slug].webp` (1600x900), then run `npm run assets:og` to make its 1200x630 JPG for social previews. Credit it in `design-source/stock-credits.md`.
- Scheduled publishing: a post shows only when `draft` is false and its pubDate (07:00 IST) has passed at build time. Everything reads posts through `getPublishedPosts()` in `src/data/journal.ts`.
- Review future posts locally with `SHOW_SCHEDULED=true npm run dev`. Never set it in production.
- `<PostLink slug="...">text</PostLink>` links only once the target is published, otherwise it renders plain text.
- Daily rebuild: `.github/workflows/daily-publish.yml` calls a Cloudflare Pages deploy hook at 07:00 IST. Create the hook in Cloudflare Pages (Settings, Builds, Deploy hooks) and save its URL as the repo secret `CF_DEPLOY_HOOK`.

## Performance and caching

- **No client-side router.** Page-to-page transitions use the browser's native cross-document View Transitions (`@view-transition` in `global.css`, with the header held still). The Astro `ClientRouter` was removed because it added 300 to 450ms of main-thread blocking per page and cut mobile Lighthouse from about 97 to 81 to 87. Browsers without native support simply navigate normally. Do not add `<ClientRouter />` back without re-measuring.
- **Scroll reveals** (`src/scripts/reveal.ts`) use one IntersectionObserver that runs when the browser is idle. Sections below the fold fade up as they scroll in. They are never hidden if JavaScript fails, and nothing animates under `prefers-reduced-motion`. Every page script runs as soon as the page is parsed, so there are no router events to wait for.
- **Prefetching:** a `speculationrules` block in `BaseLayout.astro` prefetches a page when you hover a link (Chrome only, no JavaScript).
- **Caching headers** are in `public/_headers`: hashed files in `/_astro/` are cached for a year (`immutable`), unhashed icons and social images for a week, small files like `robots.txt` and the sitemap for an hour. HTML revalidates on every visit so a new deploy shows straight away. The same file sets security headers (`nosniff`, referrer policy, `X-Frame-Options`, permissions policy). There is no Content-Security-Policy yet: it needs care because of inline scripts and styles, Google Maps and JSON-LD.
- **Cloudflare Web Analytics:** if the Cloudflare dashboard has Web Analytics auto-injection on, it adds a 10 KB beacon script to every page and lowers mobile scores by a few points. Turn it off in the dashboard (Analytics and logs, Web Analytics) if you do not use it.
- **Check before release:** `npm run build && npm run check:dist && npm run seo:audit`, then Lighthouse mobile on the built site (`npm run preview`). Latest local results: mobile 96 to 100 on all 14 page types checked, desktop 100.

## Deploy to Cloudflare Pages

1. Push the repo to the `agencystringhead-wq` GitHub org.
2. In Cloudflare Pages, create a project from the repo.
3. Settings:
   - Framework preset: Astro
   - Build command: `npm run build`
   - Build output directory: `dist`
   - Environment variable: `NODE_VERSION=20`
4. Add the custom domain, then update `site` in `astro.config.mjs` and `url` in `src/data/site.ts`.
